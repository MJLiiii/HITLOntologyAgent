## Plugin contract established from source

The [template entry](https://github.com/trustgraph-ai/ui-plugin-template/blob/9b8763e0e9c833477004c59aafb5d5530d13d4a9/src/index.ts) exports a React component as default. The [portal loader](https://github.com/trustgraph-ai/trustgraph-ui/blob/02efcac8adf04a1de1a4f601c1ecbb70ed910d6d/packages/portal/src/loadRemotePlugin.ts) reads `window[globalName]`; a function is the default component, otherwise it selects `componentName` or `default` from the export object. The [remote mount](https://github.com/trustgraph-ai/trustgraph-ui/blob/02efcac8adf04a1de1a4f601c1ecbb70ed910d6d/packages/portal/src/RemotePlugin.tsx) renders the selected component without props. The Studio entry was corrected to export the component rather than a metadata descriptor. A licensed snapshot of the actual loader is retained under `tests/contracts/fixtures/trustgraph/`.

The [host entry](https://github.com/trustgraph-ai/trustgraph-ui/blob/02efcac8adf04a1de1a4f601c1ecbb70ed910d6d/packages/portal/src/main.tsx) exposes `TrustKitShared.React`, `.ReactDOM`, `.ReactJSX`, `.TrustKit`, `.ReactProvider` and `.ReactState`. The Studio externalizes the React modules and uses these actual globals. Its IIFE global is `OntologyStudioPlugin`. The host [manifest reader](https://github.com/trustgraph-ai/trustgraph-ui/blob/02efcac8adf04a1de1a4f601c1ecbb70ed910d6d/packages/portal/src/usePluginManifest.ts) reads sections with `tab` and `components`; `infra/portal/components-entry.json` is an additive section to review and merge into the host's `packages/portal/public/config/components.json`, not a replacement for the entire host manifest.

The plugin is an integration artifact, not a hosted deployment. Its Studio API is same-origin `/api/v1`; a real portal must proxy those project-owned routes to Studio and establish an approved identity bridge. TrustGraph's native `/api/v1` may already use that namespace, so route collision must be resolved in deployment configuration. The current loopback session is unsuitable as a shared-host authentication bridge. Do not embed service secrets or treat a native ontology-editor mutation as an approved Studio release.

## Python gateway source contract

The pinned [Api source](https://github.com/trustgraph-ai/trustgraph/blob/25d5d56ef6ee32a15dcd6710b9e1ab8c42419027/trustgraph-base/trustgraph/api/api.py) defines `Api(url, timeout=60, token=None, workspace="default")`, then `api.flow().id(flow_id)` and `api.library()`. The constructor appends `/api/v1/` to the supplied server base URL. Workspace is explicit; a collection or flow is not an authentication boundary.

The [library client](https://github.com/trustgraph-ai/trustgraph/blob/25d5d56ef6ee32a15dcd6710b9e1ab8c42419027/trustgraph-base/trustgraph/api/library.py) provides `add_document(document, id, metadata, title, comments, kind="text/plain", tags=[], on_progress=None)`, `start_processing(id, document_id, flow="default", collection="default", tags=[])`, `get_processings()` and `get_document_content(id)`. Starting processing returns `{}`; that response does not prove completion. A gateway still needs observed processing/provenance contracts and stable chunk/page/subgraph identities before freezing retrieved evidence.

The [flow client](https://github.com/trustgraph-ai/trustgraph/blob/25d5d56ef6ee32a15dcd6710b9e1ab8c42419027/trustgraph-base/trustgraph/api/flow.py) provides `triples_query(s=None, p=None, o=None, g=None, collection=None, limit=10000, user_context=None)` and `graph_rag(query, collection="default", entity_limit=50, triple_limit=30, max_subgraph_size=150, max_path_length=2, ...)`. Despite its stale string-return docstring, the inspected `graph_rag` implementation returns `TextCompletionResult(text, in_token, out_token, model, sources)`. Do not treat a generated answer or unverified `sources` entry as resolved evidence. No Studio live gateway has been asserted from these signatures alone.

## Implemented optional gateway

`services/api/src/oe_studio/integrations/trustgraph/` now implements the project's async ingest, ingestion-status, retrieve and evidence-resolution contracts. `PinnedTrustGraphGateway` invokes the actual SDK through bounded synchronous calls; `FakeTrustGraphGateway` is explicitly labelled `fake` and supplies controlled offline fixtures. The application still uses its local provider. Environment values alone do not switch the live application to TrustGraph.

The optional `trustgraph` dependency group pins the [official trustgraph-base 2.11.1 source distribution](https://pypi.org/project/trustgraph-base/2.11.1/) by URL and SHA-256 `5af4a53f1dbdfc20f9fbcc0c5b9819d32e86413228ee43193c198dc488d8098a`; all transitive dependencies are in `uv.lock`. Its inspected API files match the pinned repository source (the locally saved flow/library snapshots had only a final blank line trimmed). Runtime construction checks distribution version and the exact installed hashes of `api.py`, `flow.py`, `library.py` and `types.py`. The upstream package omits its imported `aiohttp` dependency, discovered by actually importing it; the optional group supplies the explicit `aiohttp==3.14.5` pin. The upstream source files are unmodified.

```sh
# Keep optional integration verification separate from the default local environment.
UV_PROJECT_ENVIRONMENT=.venv-trustgraph uv sync --frozen --extra trustgraph
.venv-trustgraph/bin/python -m pytest tests/contracts/test_trustgraph_gateway.py -q
```

This isolated command produced **12 passed and 1 skipped**: actual installed SDK calls were exercised with controlled HTTP responses, and the live-service probe was skipped. Tests check server-selected workspace, collection and flow; distinct upload/submission; stable retry identity; configuration mismatch; missing processing records; frozen source/chunk hashes and exact byte spans; fabricated quotations; malformed/unknown sources; retrieval limits; raw graph and literal fields; and unavailable completion/provenance. An optional real authenticated read runs only with `OE_TG_LIVE_READONLY=1` plus the configured URL/workspace/flow/collection/token. It calls `get_processings()` and performs no upload, publication or ontology mutation. It is not the full live ingestion/provenance milestone.

All request models forbid extra fields, including workspace/endpoint overrides. Trusted server `Binding` objects supply endpoint, credential, workspace, flow, collection and approved seed/config hashes. `binding_from_environment` is a startup helper; it is not an HTTP endpoint. Document and corpus registries are passed by the trusted server. An unauthorized project/source/corpus fails before retrieval. Credentials are excluded from manifest hashes, exports and sanitized errors.

The source-proven completion limitation remains explicit: an upload and `start_processing()` return **queued**. An active processing record yields **processing**; disappearance yields **unknown**, never completed. `completion_supported` and `corpus_freeze_allowed` remain false for real SDK status observations because no inspected API establishes a success/error completion event. Only the explicitly fake test provider has a simulated completed fixture, labelled as such. The legacy one-shot helper is process-local. The application now uses a separate durable preparation/submission/recovery contract in the existing Job/Item ledger; see [selected import contract](trustgraph-import-contract.md). Its explicit selected snapshot does not reinterpret status observations as global completion.

Retrieval retains GraphRAG's SDK result as a diagnostic artifact and separately preserves source-bearing evidence and graph context. The high-level SDK `triples_query()` drops literal metadata and named-graph fields, discovered by the real SDK wire test. The gateway therefore invokes the same inspected fixed `service/triples` path through `FlowInstance.request()` and preserves the entire raw response rather than reconstructing RDF term details. The caller never supplies that service path or workspace payload. Returned graph context includes the exact server-registered named graph and collection.

The real 2.11.1 gateway rejects SDK `get-document`/`list-children` operations. Evidence uses supported `get-document-metadata` plus full content, and original-document source URIs resolve only to that document’s registered frozen children. Evidence currently supports registered UTF-8 text sources and child-document chunks whose upstream document identity, parent, source hash, chunk hash, byte span and full quotation all agree. Arbitrary extraction chunk URIs, PDF transformations and undocumented trace endpoints are not guessed. Unmapped sources, changed bytes, fabricated quotes, unverified corpus provenance or reached limits set `review_eligible=false` with reasons. The generated GraphRAG answer is not substituted for evidence or placed in the agent manifest. A trace artifact is not a verified source relationship merely because it exists.

The gateway enforces chunk/triple bounds and records an explicit conservative UTF-8-byte basis for the requested token budget; the SDK supplies no matching tokenizer, so observed token count stays null. Reached limits block eligibility rather than silently dropping evidence. Exact model token accounting requires the eventual deployment's tokenizer/usage contract.

To add external evidence to a local project, install the pinned optional SDK and configure a private server-owned project binding. Prepare and persist the approved seed/configuration before enqueue, recover only an exactly observed prior submission, then explicitly select verified registered chunks. Studio copies their exact bytes, local offsets and source/extraction lineage into a new immutable corpus while preserving old corpora and the approved ontology. The [durable import contract](trustgraph-import-contract.md) defines the bounded text profile, failure cases, API routes and live reproduction. Upstream global completion and remote storage immutability remain unsupported; selection never creates an ontology approval.

The later live verification uses the exact 2.11.1 image digest in `infra/portal/pipeline-pins.json`, not the earlier cached 2.8.17 image. [The pipeline report](trustgraph-pipeline-smoke.md) records all four diagnostic attempts, the separately mounted bounded model provider, successful source/provenance plumbing, and the ontology-guided answer-quality failure. No successful snapshot is presented as a correct answer or research result.
