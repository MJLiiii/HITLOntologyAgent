# Scoring and interpretation

The runnable `demo-v1` is a synthetic engineering exercise. Scripted outputs and repeated deterministic replicates cannot establish model performance, expert benefit, or a research effect. D remains `waiting_human`; no reviewer ratings or review times are invented.

`model-pilot-v1` instead calls the configured Ollama model. It freezes one evidence packet and one actual generated initial candidate per replicate; A stops there, B receives up to two self-revisions without reports, and C receives up to two repairs using failed development CQ outcomes only. D reuses C's exact automated calls and output. All frozen outputs receive the same development Jena and OntoCheck evaluation. This single synthetic task is an engineering smoke, not an independent sample of real-domain tasks or a confirmatory model comparison. Actual human review creates a separate linked post-review record and reruns the original frozen workload. No scripted fallback replaces a model failure.

The study's proposed expert rubric uses separate 1–5 ratings for correctness, clarity, necessity, and modelling appropriateness. Anchor 1 means a major defect that prevents the intended use; 3 means useful with material corrections; 5 means fit for the agreed task with no identified substantive defect. Domain experts must refine these anchors and approve example cases before the study. Keep each dimension and each independent rater separately; consensus alone does not establish agreement. A source citation is not proof that the cited passage supports an axiom.

Executable demo metrics use three finite, explicit ASK oracles: hierarchy membership (true), ownership (true), and Payroll-as-Team (false). They measure exact development-case answers under the admitted RDFS profile. The negative expectation belongs to the finite synthetic reference set; it does not assert that all unobserved real-world facts are false. Reasoning pass rate is passing expected outcomes / all scheduled cases. An engine error, timeout, unsupported case, or missing result remains in that denominator.

ASK answer precision is TP/(TP+FP), recall is TP/(TP+FN), and F1 is 2TP/(2TP+FP+FN). If any scheduled ASK case is unevaluable, these three ratios are missing (`unevaluable_cases`); zero denominators are missing (`zero_denominator`). Required answer accuracy counts correct Boolean answers / all scheduled ASK cases, alongside evaluable accuracy and explicit error counts. Registered [synthetic tasks](SYNTHETIC_TASKS.md) may also contain reviewed SELECT and SHACL cases; those remain in the all-case reasoning pass rate but are excluded from Boolean answer classification. They do not expand the original model pilot's frozen scope.

OntoCheck vocabulary coverage is overlapping workload terms / workload terms, and vocabulary utilisation is overlapping workload terms / ontology terms. Neither is answer precision, answer accuracy, grounding, or logical consistency. Fitness results retain raw upstream diagnostics and manifests; approximate matches do not approve mappings. Failed assessments have null scores with reasons.

For the future study, freeze independent held-out answers, mappings, source-error labels, grading anchors, exclusions, reviewer allocation and common correction limits before confirmatory runs. A and D must include all expert time from first inspection through acceptance, including review and rework; unsuccessful cases remain with right-censored acceptance times. Report task-level paired distributions and uncertainty only when the number of independent tasks permits it.
